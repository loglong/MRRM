<task type="auto">
  <name>Task 2: Path assignment to patient demand</name>
  <read_first>backend/src/paths/paths.service.ts, prisma/schema.prisma</read_first>
  <action>
Implement path assignment and instance tracking:

1. PathAssignmentService (in paths.service.ts):
   - assignToPatient(pathId, patientId, demandId, orgId, startDate = new Date()):
     - Verify path template exists and is ACTIVE
     - Verify patient exists
     - Verify demand exists and is linked to patient
     - Create PathInstance record
     - For each PathStep in template (ordered by stepOrder):
       - Calculate cumulative dueDate from startDate + sum of previous executeDays
       - Create PathInstanceStep with status=PENDING (first step gets status=IN_PROGRESS)
     - Return created instance
   - getInstance(id): Get instance with steps
   - getPatientInstances(patientId): List all instances for patient
   - getDemandInstances(demandId): List all instances for demand
   - completeStep(instanceId, stepId, notes): Mark step COMPLETED, advance currentStep to next PENDING
   - skipStep(instanceId, stepId, reason): Mark step SKIPPED, advance currentStep
   - cancelInstance(id): Set status=CANCELLED

2. Progress tracking (computed from PathInstanceStep records):
   - completedCount: count where status = COMPLETED
   - currentStep: first step where status = IN_PROGRESS
   - pendingCount: count where status = PENDING
   - overdueCount: count where status = OVERDUE (dueDate < now AND status = PENDING)

3. PathController additions:
   - POST /path-templates/:id/assign: Assign to patient/demand (body: {patientId, demandId})
   - GET /path-instances: List all instances (filterable by patientId, demandId, status)
   - GET /path-instances/:id: Get instance with steps
   - PUT /path-instances/:id/steps/:stepId/complete: Complete step (body: {notes})
   - PUT /path-instances/:id/steps/:stepId/skip: Skip step (body: {reason})
   - PUT /path-instances/:id/cancel: Cancel instance
   - GET /patients/:patientId/path-instances: Patient's path instances
   - GET /demands/:demandId/path-instances: Demand's path instances

4. Overdue detection (in PathAssignmentService or separate cron):
   - detectOverdueSteps(): Find all PathInstanceStep where:
     - status IN (PENDING, IN_PROGRESS)
     - dueDate < now
   - For each overdue step:
     - Update status to OVERDUE
     - Create Notification for responsible user (via PathStep.responsibleRole -> find user)
     - NotificationType: PATH_OVERDUE
     - Link: /path-instances/:instanceId

5. Integration with step completion:
   - When step completed via completeStep():
     - If next step exists: set its status = IN_PROGRESS
     - If next step exists and dueDate has passed: set status = OVERDUE immediately
   - When step skipped via skipStep():
     - Advance to next step (same logic as completeStep)

6. Cron job for overdue detection:
   - Run every hour via @nestjs/schedule
   - Use existing RabbitMQ infrastructure from Phase 01 for async processing
   - Find all overdue steps, bulk update status, bulk create notifications
